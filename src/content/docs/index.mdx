## Why rumbo

<CardGrid>
	<Card title="Any model, any interface, any language" icon="puzzle">
		Providers and front ends are programs that speak a small JSON-RPC protocol over stdio. The
		built-in ones use the same protocols as the ones you write; none gets a shortcut.
	</Card>
	<Card title="History you can replay" icon="document">
		A session is an append-only log you can read. Every request sent to the model can be rebuilt
		from it, a run cut short resumes where it stopped, and a branch goes on from any of your
		messages.
	</Card>
	<Card title="Built for the provider's cache" icon="rocket">
		Each request extends the one before, so the provider reads it from its cache. rumbo tells you
		when a request misses it, since the rest is paid for again.
	</Card>
	<Card title="One host, many sessions" icon="list-format">
		Runs go on in other sessions while you work in a new one, and you can tell a run something
		without stopping it.
	</Card>
	<Card title="Providers describe themselves" icon="setting">
		Their models, options, and functions, down to a sign-in that asks you for a code, show up in
		every front end without the front end knowing them.
	</Card>
	<Card title="Small and general" icon="star">
		A short fixed system prompt, four tools, no telemetry. It knows no kind of work: it does what
		your task and your `AGENTS.md` ask, programming or not.
	</Card>
</CardGrid>

## How it works

<div class="diagram">
	<img
		src="/diagrams/how-it-works.svg"

		width="1000"

</div>

The host is the only part that is always rumbo. It runs the loop: it asks a provider for the next
message, runs the tools the model calls (`read`, `write`, `edit`, and `bash`), and repeats until
the model stops calling tools. The interface you use and the model behind it are separate programs
you can replace. Read more in the [architecture](/reference/architecture/).

## What it leaves out, on purpose

rumbo is a general agent harness, and these are decisions, not gaps. It does not judge the model's
work, send context nobody asked for, limit what the agent may do, or track your files. There is no
plan mode, no subagents, and no permission prompts: a shell reaches everything else, and what a
task needs comes from the task and your instructions. Read why in [design](/concepts/design/).
